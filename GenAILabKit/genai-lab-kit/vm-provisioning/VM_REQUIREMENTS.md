# VM Lab Requirements — GenAI Lab Kit

The lab vendor provisions and **validates** every VM image before participant
access. Participants do zero setup.

## 1. Base image

| Component | Requirement |
|-----------|-------------|
| OS | Ubuntu 22.04 LTS (preferred) or Windows 11 |
| CPU | 4 vCPU |
| RAM | 8 GB minimum |
| Storage | 30 GB |
| Python | 3.10 or 3.11 (single system interpreter, on `PATH`) |
| Internet | Outbound HTTPS to `api.openai.com` (and any other model host a lab uses) |
| IDE | JupyterLab/Notebook **and** VS Code, both launchable from the desktop |

## 2. Python packages

Install the aggregated set (union of all labs):

```bash
python -m pip install -r vm-provisioning/requirements.txt
python -m ipykernel install --name python3 --display-name "Python 3"
```

`vm-provisioning/requirements.txt` is generated by
`tools/aggregate_requirements.py` from each lab's `05_CONFIG/requirements.txt`.
Re-run it whenever a lab is added or changed.

## 3. Secrets

For each lab, copy its `05_CONFIG/.env.example` to `05_CONFIG/.env` and fill in
the real values (e.g. `OPENAI_API_KEY`). Alternatively set the variables in the
VM environment. Rules:

- The real `.env` / key is **never** placed in a participant solution-sharing area.
- The key is a **vendor-managed** project key with usage limits, not a personal key.
- Participants must never be asked to create or paste a key.

## 4. Files placed on the VM per lab

```
<lab-id>/
├── 00_START_HERE.md
├── 01_TASK_GUIDE/
├── 02_STARTER_CODE/         # participant notebook + starters
├── 03_SOLUTION_GUIDE/       # REMOVE before participant access; release later
├── 04_DATA/
├── 05_CONFIG/               # .env (filled), requirements.txt
├── 06_REFERENCE/
├── scripts/
└── chroma_db/ (or other working dirs, empty)
```

> `03_SOLUTION_GUIDE/` is trainer-only. Keep it out of the participant image and
> hand it out after the session.

## 5. Pre-access validation (run as the participant user)

For every lab on the image:

```bash
cd <lab-id>
python scripts/setup_check.py --live        # packages + key + data + 1 API call
python scripts/validate_solution.py         # solution passes end-to-end
```

Both must exit `0`. Capture the output as the provisioning evidence.

## 6. Reset between cohorts

- Delete each lab's `chroma_db/` (and any `*.sqlite3`, `.ipynb_checkpoints/`).
- Restore `02_STARTER_CODE/` from the pristine copy.
- Rotate the API key if usage limits were hit.
